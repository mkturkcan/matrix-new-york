# Matrix New York

Street View initial observations and a kinematic vehicle controller for pretrained action-conditioned video world models, applied to New York City.

Project page: https://mehmetkeremturkcan.com/matrix-new-york/

## Summary

For a query location we retrieve the nearest Google Street View panorama captured by a Street View car (via [streetlevel](https://github.com/sk-zk/streetlevel)), reproject it to a 1280×704 perspective view along the capture heading, remove near-field vehicles (Mask2Former, Cityscapes classes; LaMa inpainting), and insert a vehicle mesh from [MeshFleet](https://huggingface.co/datasets/DamianBoborzi/MeshFleet) rendered under a chase camera. Driver inputs (throttle, steering) are integrated by a kinematic bicycle model and mapped to the action spaces of two pretrained world models. No model is fine-tuned.

| | Matrix-Game-2.0 GTA-drive | Matrix-Game-3.0 |
|---|---|---|
| Viewpoint | third-person (trained on GTA V driving) | first-person |
| Keyboard | `[W, S]` = PWM of throttle / brake, 1 s period | `W` = PWM of `min(v / 10 m/s, 1)`, 0.5 s period |
| Mouse yaw | `0.1 · steer` (training data uses ±0.1 for A/D) | chase-camera yaw rate / 15° per frame |
| Ego vehicle | generated by the model | drawn from 17 renders indexed by the controller's relative yaw |
| Conditioning frame | with inserted vehicle | vehicle-free (inpainted) |
| Output | 352×640, 12 fps | 704×1280, 17 fps |
| Throughput (1× RTX PRO 6000, after load) | ≈18 frames/s | ≈3.6 frames/s (bf16, no int8, synchronous VAE) |

## Observations

- **GTA-drive** propagates the inserted vehicle and produces non-holonomic motion: steering changes heading and the vehicle yaws in the image, with no lateral translation. Within roughly 8–12 s the scene, and to a lesser degree the vehicle, drift toward GTA V appearance (simplified geometry and facades, sky and water shading, vehicle identity). The model also reproduces the game's minimap in the lower-left corner, which the input overlay partially covers; the raw outputs (`*_world.mp4`) show it.
- **Matrix-Game-3.0** has no ego-vehicle prior. A vehicle composited into the conditioning frame is treated as static scene content and passed through within ~1 s, leaving a smear. We therefore condition it on the inpainted, vehicle-free frame and draw the vehicle ourselves at the relative yaw ψ − ψ_c given by the controller.
- **Matrix-Game-3.0 forward speed is not controllable through its action interface.** It translates a fixed amount per frame while `W` is held. Scaling the camera translation used for its Plücker-ray conditioning by 3× left the output essentially unchanged (mean Farnebäck flow 0.65 vs 0.66 px/frame at 320 px width). Lower `W` duty cycles reduce speed (flow 0.04 px/frame at 12% duty), so duty cycle can slow the model but not speed it up.
- Large heading changes away from intersections steer either model into facades. Turn presets are only meaningful when the first frame is at an intersection.

## Vehicle model

Inputs: throttle/brake `u ∈ [-1, 1]`, steering `s ∈ [-1, 1]` (low-pass, τ = 0.15 s), at the backend frame rate.

$$
\dot v = a^{+}\max(u,0) + a^{-}\min(u,0) - c\,v,\qquad
\delta = \frac{s\,\delta_{\max}}{1 + v/v_{\mathrm{ref}}},\qquad
\dot\psi = \frac{v}{L}\tan\delta,\qquad
\dot\psi_c = \frac{\psi-\psi_c}{\tau_c}
$$

L = 2.7 m, δ_max = 32°, v_ref = 6 m/s, a⁺ = 3 m/s², a⁻ = 7 m/s², c = 0.12 s⁻¹, v ≤ 25 m/s, τ_c = 0.35 s. Lane changes are steering doublets (s = ±0.7 for 0.5 s each). Route presets: `cruise`, `highway`, `downtown`, `slalom`, `turn_left`, `turn_right` ([`nycdrive/vehicle.py`](nycdrive/vehicle.py)). Custom routes are JSON lists of `[seconds, throttle, steer]`.

## Setup

```bash
git clone https://github.com/mkturkcan/matrix-new-york && cd matrix-new-york
pip install -r requirements.txt          # install torch + flash-attn for your CUDA first

# Matrix-Game-3.0 code and weights (~43 GB without base_model/)
git clone --filter=blob:none --sparse https://github.com/SkyworkAI/Matrix-Game.git third_party/Matrix-Game
git -C third_party/Matrix-Game sparse-checkout set Matrix-Game-3
hf download Skywork/Matrix-Game-3.0 --local-dir checkpoints/Matrix-Game-3.0 --exclude "base_model/*"

# Matrix-Game-2.0 GTA-drive: the inference code and checkpoint were removed upstream; use the original revisions
mkdir -p third_party/mg2_gta
git -C third_party/Matrix-Game archive 756776d^ Matrix-Game-2 | tar -x -C third_party/mg2_gta
hf download Skywork/Matrix-Game-2.0 --revision f1729d99a80e0f07993a77d7dad4a3190e23c2c8 --local-dir checkpoints/Matrix-Game-2.0 \
  gta_distilled_model/gta_keyboard2dim.safetensors gta_distilled_model/config.json Wan2.1_VAE.pth \
  models_clip_open-clip-xlm-roberta-large-vit-huge-14.pth xlm-roberta-large/tokenizer.json \
  xlm-roberta-large/tokenizer_config.json xlm-roberta-large/special_tokens_map.json xlm-roberta-large/sentencepiece.bpe.model
```

Tested with torch 2.12 + CUDA 13.0 and flash-attn 2.8 on RTX PRO 6000 Blackwell GPUs. Each clip runs on one GPU.

## Usage

```bash
# initial observations
python -m nycdrive.prepare_inputs                                   # curated scenes
python -m nycdrive.prepare_inputs --random --seed 7                 # random location (Manhattan / Brooklyn / Queens)
python -m nycdrive.prepare_inputs --lat 40.7497 --lon -73.9877 --name herald_square [--heading DEG]
python -m nycdrive.car_bank --scenes herald_square                  # yaw renders for the Matrix-Game-3.0 backend

# rollouts
python -m nycdrive.drive_gta --scene data/inputs/fdr_drive --route highway            # Matrix-Game-2.0 GTA-drive
python -m nycdrive.drive     --scene data/inputs/fdr_drive --route highway            # Matrix-Game-3.0
python -m nycdrive.drive     --scene data/inputs/fdr_drive --interactive              # step-wise keyboard input

# batch rendering and project page
python scripts/render_showcase.py configs/showcase_gta.json --gpus 0,1,2,3
python scripts/render_showcase.py configs/comparison.json   --gpus 0,1,2,3
python scripts/build_site.py
```

Outputs per rollout: `<name>_world.mp4` (raw model output), `<name>_hud.mp4` (with input overlay), `<name>_actions.npz` (issued actions and controller state).

## Limitations

- Only the first frame is observed. Everything after it is sampled from the model's prior and does not correspond to the real street network.
- The Matrix-Game-3.0 ego vehicle is a 2D layer: it is not occluded by, does not shadow, and does not interact with generated content.
- Street View coverage, capture date and weather depend on the panorama nearest the query. `streetlevel.streetview.find_panorama` no longer works because Google decommissioned the endpoint behind it; `prepare_inputs.py` queries coverage tiles instead.
